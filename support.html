What AL Tools does

AL Tools is an SSH client for your own Linux servers. It gives you a file browser with SFTP transfers (including an administrator mode for protected folders), a terminal that keeps running on the server between visits, and an AI Workspace that drives the Codex or Claude Code command-line tools installed on your server. Everything runs on the server; the app only displays it.

Requirements

A server reachable over SSH (port 22 or another port) with a user account and python3 3.7 or newer. For the persistent terminal, tmux on the server is recommended. For the AI Workspace, the codex or claude CLI must be installed on the server and signed in under your own account; AL Tools does not include or provide access to any AI model.

Getting started

Open the Servers tab and add your server's address, port and user name. On first connection the app shows the server's host-key fingerprint; compare it with your server and accept it once. You can then sign in with a password or generate an SSH key in the app and install its public half on the server. Use Browse for files, Terminal for a shell, and AI to choose a workspace folder and a CLI.

Common problems

"Check CLI" says the tool is missing

Non-interactive SSH sessions often have a shorter PATH than your terminal. Enter the full path to the executable in the chat's Workspace settings (for example /home/you/.local/bin/codex), or add its folder to ~/.profile rather than ~/.bashrc.

The AI run stops immediately, or saved conversations are missing

The CLI must be able to write its own session files. Check that ~/.codex (or ~/.claude) and everything under it belongs to your user and is writable — running the CLI once with sudo is the usual cause of root-owned files there:

find ~/.codex ! -user "$(id -un)" -ls | head
sudo chown -R "$(id -un)" ~/.codex

Also make sure the CLI is signed in on the server (codex login or claude).

"The CLI bridge did not start on the server"

python3 is not installed or not on the path for SSH sessions, or the workspace folder is not writable. Run python3 --version over SSH to confirm.

Host key changed

The app refuses to connect if a server's host key differs from the one you accepted earlier, because that can indicate an interception. If you reinstalled the server or rotated its keys, remove the saved identity in the Security tab and accept the new fingerprint.

Terminal does not persist between visits

Install tmux on the server (sudo apt install tmux on Debian/Ubuntu). Without it the shell still works but ends when the connection drops.

Where are my downloads?

In the Downloads screen inside the app, and in the Files app under On My iPhone/iPad → AL Tools. On Mac they are in your Downloads folder under "AL Tools".
